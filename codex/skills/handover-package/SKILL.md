# 移交资产打包

## 精神（一句话）

**移交是把资产完整交出去，不是教会对方做事。** 交付物只说"你有什么、在哪里、怎么部署"，永远不说"你没有什么、被限制什么、我们做了什么处理"。去注释、删文档是对我方资产的保护动作——做了不宣告。

## 打包流程

### 1. 独立副本（绝不动原项目）

复制到独立目录（惯例 `~/IdeaProjects/移交资产/`），rsync 排除：
`node_modules` `target` `dist` `.next*` `.git` `logs` `test-results` `playwright-report` `coverage` `.tanstack` `.turbo` `*.log`

### 2. 清理

- **删全部代码注释**：Java 的 `//` `/* */` JavaDoc；TS/TSX/JS 必须用 AST（@babel/parser）定位注释区间，**不要自写正则/词法器**——实测会吃掉 `catch { /* ignore */ }` 的花括号造成语法错误。改完自动重新解析、解析失败即回滚该文件。
- **保留（是代码不是注释）**：shebang、`/// <reference>` 三斜线指令、eslint-disable / @ts-nocheck / @ts-expect-error、字符串字面量里的 `//` 与 `#`（URL、`#fff`、正则）、`.env` 文件。
- **卸载整套 OpenAPI/Swagger**：`@Schema(description=...)`、`@Operation(summary=...)`、`@Tag` 虽然是编译进字节码的代码，但 description 里装的是**业务语义**（字段含义、取值优先级、内部命名规则），比普通注释泄露得更多——一并清除。顺序不能错：**先删注解与 `import io.swagger.*` → 删 OpenApiConfig → 删 application*.yml 的 springdoc 段 → 最后移 pom 依赖**。先移依赖会让满屏 import 报错。多行注解要整体删，别只删首行留下孤立括号。
- **清 SQL 注释**：独立 `.sql` 文件与 `@Query("...")`/原生 SQL 字符串里的 `--` 与 `/* */`。SQL 是运行时才解析的，编译器不会兜底——改错线上才炸，逐条确认，不确定就保留。
- **删所有 .md**（含 README/CLAUDE/AGENTS/docs 内嵌截图目录）。
- **删残余杂物**：`.tsbuildinfo`、`.DS_Store`、旧构建包 tar.gz、本地开发密钥文件（如 `k8s/local/*secrets*.yaml`——先实测其 key 作用域再决定，dev 桶级也不进包）。

### 3. 验证（硬门槛）

- 后端 `mvn -DskipTests clean package` → BUILD SUCCESS（注意 JDK 版本陷阱：Lombok 在过新 JDK 下注解处理静默失效，报海量 cannot find symbol——用项目锁定的 JDK 版本）。
- 前端 `npx tsc --noEmit` 与**改动前基线逐条对比**——只允许基线里已有的错误。
- 包内密钥实测：能登录、能到达清单所述的每一项资产。

### 4. 凭据纪律

- **最小作用域**：R2 给桶级 token、Cloudflare 给域级 token、Firebase 只到本项目。账号级/全局凭据（Global API Key、AWS key、跨桶 token）**绝不进包**——发现生产在用的就是账号级 key 时，新建作用域受限的替换生产后再交付同一把。
- **交付前实测隔离**：用包内凭据访问无关资源必须得到 AccessDenied / Forbidden 才算过。
- **中性命名**：密钥文件名不带 viewer/admin 等角色字样（如 `baodiantimes.pem`）。
- 服务器侧权限用技术手段实现（RBAC 命名空间隔离、无 sudo 账号），落在服务器上，不落在文档里。

## 交付清单（唯一说明文件）

纯文本 `.txt`，不是 md。结构固定为五节，只说什么是什么：

```
一、本目录内容        每项一行：名字 + 是什么
二、线上资产位置      服务器/各服务/数据库/缓存/对象存储/认证/域名解析/域名注册
                     ——每项：是什么、坐标在哪、凭据是什么
三、技术栈            一行一项
四、部署结构          一张拓扑图
五、部署方式          各端构建命令原样列出
```

### 语言红线（逐条 grep 自查后才算完成）

1. **零教学语言**：不写 建议/注意/务必/重要提醒/步骤解释/故障排查/接手后建议/"见第几节"导航。
2. **零限权表述**：不出现 只读/权限范围/无权/被拒绝/管理员密钥/仅限。**枚举"该账号可以做 X、Y、Z"同样等于暗示边界，一样禁止**——账号与凭据只写如何获得、如何使用（如：域名管理→收邮件→注册账户即得）。
3. **零处理痕迹**：不写"已去除注释/不含/单独交付/为保护而删除"；内部运维史（"历史上出过 N 次故障"）不外泄。
4. **零无关基础设施**：另一台服务器的 IP/编号、同机同集群的其他项目名、主库备库/双机/浮动地址等内部机制一概不出现。数据库容灾只写一句"内网地址 + 异地容灾高可用"。对系统而言数据库就是一个内网 IP。
5. 自查扫描词表：`只读|权限范围|无权|被拒|仅限|管理员|子账户|可以做|该账号|建议|注意|务必|提醒|已去除|不含|单独交付|历史上|主库|备库|双机|浮动|漂移` + 所有无关服务器 IP 与项目名。

## 打包与发送时机（吃过亏，务必守住）

**内容全部定稿之后才打包，打包之后不再改内容。** 移交件一旦发出就收不回——对方是否已下载不可控，追回意味着要么解释扣留了什么（违背移交精神），要么反复重发引起疑虑。

- 打包与内容修改**绝不并行**。清理、卸载、改文档还在进行时，不打 zip。
- 打包后若内容又变了：**旧包必须作废重打**，并在重打后核验压缩包**内部**内容（`unzip -p <zip> <某个代表性文件> | grep <应已清除的特征>`），不能只看目录里的散文件干净就以为包也干净。
- 发送前最后一步：核对包的时间戳晚于所有内容修改的时间戳。

## 完成标准

独立目录内：源码副本（编译验证过）+ 密钥文件（实测过）+ 一份交付清单（红线扫描清零）。除此之外零 .md、零 .git、零构建产物、零本地开发密钥、零 `.DS_Store`。

**验证要自己复现，不能只采信执行方的报告**：grep 残留数、编译退出码、关键结构点数（如 Spring 绑定注解 `@PathVariable`/`@RequestParam`/`@RequestBody` 删改前后数量必须一致——批量删注解最容易连带吃掉相邻的参数注解）。
